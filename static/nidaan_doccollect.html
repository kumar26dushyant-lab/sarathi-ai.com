The four things that make it work

One list, per claim type. Change the type and the list rebuilds — and it is editable, because no standard list survives a real case.
Tick what to ask for. Not the whole list every time: three documents asked for clearly beat eleven asked for at once.
Arrivals tick themselves. A document sent on WhatsApp lands against the item, turns green, and shows how it came — with remove, because the wrong file will be sent.
Everyone involved is copied. The complainant is asked; the branch, CP and subscriber see the same request, so nobody is chasing blind.

04

When a document arrives

  1. It lands on the claim by the sender's number, and is stored.
  2. We guess which checklist item it is — from what we last asked for, and from the file itself.
  3. If we are confident, it ticks green and the complainant is told "mil gaya", naming what is still left.
  4. If we are not, it sits as unmatched at the top of the window for a person to drop onto the right line. It is never silently filed against the wrong item.
  5. Remove un-ticks it and puts the request back — because the wrong file gets sent, and a checklist you cannot correct stops being believed.
The one thing I would not automate

Deciding a document is acceptable. We can tell that a PDF arrived and that it is probably the discharge summary. We cannot tell it is the right admission, legible, or complete. Green should mean received, not approved — and the person moving the claim on is the one who says it is good enough.
